# Architecture and engine reference

Why the engine is built this way: [decisions/](decisions/README.md).

## TOML workflow

Run `node engine/serve.mjs`, open its address → the most recently saved stored diagram opens, or **New diagram** (an empty folder-format diagram in memory, named by you, saved with **Save**) or **Open saved diagram** (a dialog listing the diagram folders stored in `local/`) or **Import diagram** (a `.diag.zip` from disk) → automatic arrangement → **Edit layout** and/or edit notes → **Save**. Diagram folders live in the git-ignored `local/` folder behind the server (`local/<folder>/topology.toml`, `server-types.toml`, `notes.toml`, `documents.toml`, `networks.toml`, `servers/<id>.toml`, `diagram.layout.json`); geometry is saved as `diagram.layout.json`, edited notes are written back into `notes.toml` and edited servers into their own `servers/<id>.toml`; **Export** downloads the whole in-memory diagram as one `<id>-<timestamp>.diag.zip` ([authoring.md](authoring.md#diagram-archive)); no folder picker is used, so it works in every modern browser. Start with `examples/demo/`. Format and workflow: [authoring.md](authoring.md).

Regenerate the standalone page: `node engine/browser.mjs` (`--check` checks drift). The server (`node engine/serve.mjs`, `http://127.0.0.1:8080`) binds loopback only and serves the engine page plus the JSON API described in [authoring.md](authoring.md#local-server-api); `diagram.html` opened from disk works in memory only (no Save). Tests: `node --test engine/test/*.test.mjs` ([Testing](#testing)); `package.json` scripts (`npm test`, `npm run cover`, `npm run check`, `npm run serve`) and the pre-commit hook are in [ci-cd.md](ci-cd.md#local-checks-and-the-pre-commit-hook).

New modules: `parse/toml.mjs` (authoring subset, `mergeFolder` - the folder loader that merges the per-file contents into one document and rejects keys in the wrong file - and model validation; `tomlModel(files, folder)` takes a `Map` of folder-relative path to text), `render/pipeline.mjs` (`renderModel`: the one render pipeline - geometry check, routes, networks, types, OS, SVG, edge key, view box, data JSON, page; pure, no file or DOM access, bundled into the page through `browser/render.mjs`) and `browser/render.mjs` (loader: saved-layout reconciliation, then `renderModel`), `parse/toml-write.mjs` (pure surgical write-back, round-trip checked against `parseToml` before returning: `setNotes(src, texts)` / `formatNotes` for the top-level `notes` key of `notes.toml`, and `setServer(src, id, fields, ctx)` which edits the top-level keys of `servers/<id>.toml` (`ctx` is the merged diagram, used for type inheritance and the unique-name check) - name, server_type, os, hardware, role, ips, dns, jobs, rmi_services, systemd_services, details; unchanged keys untouched, emptied keys removed, new keys appended after the last key; `parseToml` fills `spans.keys` with key positions for it), `parse/types.mjs` (`mergeTypes`: built-in server types merged with the file's `[[server_types]]`, shared by `parse/toml.mjs` and `resolveTypes`; for TOML models every merged type gets colour variables so the badge picker can show them), `parse/shared-networks.mjs` (the folder's `networks.toml`: BigInt CIDR parse/contains for IPv4 and IPv6, `parseNetworksFile` validation, `assignNetwork` longest-prefix match, `buildNetworks` panel rows / IP-to-network map / unassigned row; `browser/render.mjs` reads `networks.toml` from the folder and feeds the result into the existing Networks panel, network buttons and the IPs section of the details panel), `runtime/canvas/context-menu.js` (edit-mode right-click menu, one `contextmenu` listener on the document (so panels and the toolbar are covered too; text fields keep the native menu): "Add Server" on empty canvas or a region, "Add Region" on empty canvas outside every region (a second step lists the server types without a region; disabled with a message when none is left), "Duplicate server" on a server; calls `core.host.serverEditor.add(region, x, y)` / `.regionTypes()` / `.addRegion(type, x, y)` / `.duplicate(id)`, attached by the frame bridge (`browser/frame-bridge.mjs`) from the hooks of `browser/edits.mjs`, also for an unsaved new diagram; `addServer(files, { region })` in `parse/toml-write.mjs` builds the new `servers/<id>.toml`, `duplicateServer(files, id)` copies the source file text with a new `id` and `name`, `addRegion(files, { server_type })` appends a `[[regions]]` table to `topology.toml` (id and title from the type; refuses a type that already has a region), `freeRegionTypes(files)` lists the types still without one, `moveServer(files, id, region)` sets or clears the `region` key of a server file and keeps its `server_type` consistent; `runtime/canvas/edit-mode.js` calls `serverEditor.move(id, region)` when a dragged server is dropped in another region or outside all of them; in edit mode the arrow keys move the focused, selected server or region by the snap step (1 px with Snap off), Shift ten times that, through the same `model.apply` as a drag), `runtime/ui/server-edit.js` (details-panel server editor: inline name, badge picker, text fields, list rows with add/remove, Notes; Done / Enter / Esc; reports dirty state; hands commits to `core.host.serverEditor`, attached by the frame bridge from the hooks of `browser/edits.mjs`), `parse/import-servers.mjs` (pure logic of the toolbar's **Import servers** dialog: `planImport(files, entries, { server_type, region, skip })` parses each probe snippet, sanitizes invalid ids, resolves id collisions with a `-2`, `-3` suffix and duplicate names with ` (2)`, `setKeys` (in `parse/toml-write.mjs`) adds only `id` / `name` / `server_type` / `region` lines, each result is validated with `tomlModel`; `gridPlacements` finds free grid cells; `summary` builds the toolbar message; `browser/dialog-flows.mjs` (`createImportFlow`) shows the dialog and `browser/edits.mjs` adds the files through `rerenderMany`), `parse/new-diagram.mjs` (`newDiagram(id)`: the file map of an empty diagram - `topology.toml` with id and title, empty `networks.toml`, `notes.toml` and `documents.toml`, a generic `server-types.toml`; `DIAGRAM_ID`, a copy of the rule in `lib/ids.mjs`; `browser/dialog-flows.mjs` (`createNewFlow`) and `browser/app.js` (`load`) open it with an empty session `source`, so every file counts as changed and Save writes the whole folder), `lib/names.mjs` (file-name allowlist for `<folder>/[servers/]<name>`, layout name, timestamped archive name; shared by page and server), `lib/zip.mjs` (dependency-free zip writer / reader for `.diag.zip`: CRC-32, stored + deflate-raw via the platform streams, zip-slip name rules, entry / size caps enforced while inflating; runs in the page and in Node tests), `lib/diagrams.mjs` (pure logic of the pickers: `listDiagrams` from `GET /api/files` rows, `filterDiagrams`, live `nameProblem`, `sanitizeName` / `archiveDiagramName`, `packDiagram` / `unpackDiagram`; `browser/api.mjs` (`listStored`), `browser/dialog-flows.mjs` and `browser/app.js` (`importArchive`) build the Open saved diagram, New diagram and Import diagram flows from it), `lib/store.mjs` (the `local/` store, one sub-folder per diagram: recursive list, read, all-or-nothing compare-before-write; a save stages every file as a fsynced temp file, renames them all and restores the previous contents if any rename fails; leftover `.<hex>.tmp` files are swept at start and before each save, request guards; `handleApi` is network-free and unit-tested), `runtime/ui/notes-edit.js` (Notes panel editor: Add note, click-to-edit, Done / Esc / Ctrl+Enter, Delete; reports dirty state), `render/draw-kit.mjs` (`drawKit`: pure stroke helpers - `decimate` (1-decimal rounding, near-duplicate drop), `smoothPath`, `distToStroke` / `hits` / `hitIndex` (eraser hit-testing), `history` (undo / redo snapshots), `validate` (the `drawings` schema), `markup`; inlined as the `canvas/draw-kit` runtime module and used by `browser/render.mjs` and `page/layout-html.mjs`), `runtime/canvas/draw.js` (Select / Pencil / Eraser tools on the `#dw` layer, pointer events, Ctrl+Z / Ctrl+Y, dirty state; `browser/frame-bridge.mjs` reads `list()` / `isDirty()` / `markSaved()` and `browser/save.mjs` writes `drawings` plus unknown layout keys into `diagram.layout.json`), `browser/app.js` (wiring of the page; the modules it builds are listed in [Parser, writer and page app structure](#parser-writer-and-page-app-structure)), `browser.mjs` (standalone bundle; embeds `tools/host-probe.sh` as the `HOST_SCRIPT` constant, JSON-encoded with `<` escaped, for the header's **Host script** panel: a four-step dialog (collapsed `<details>` with the script text, `hosts.txt` example, ssh loop, pointer to **Import servers**), each code block with its own Copy button via `navigator.clipboard` with a hidden-textarea `execCommand` fallback and 1.5 s "Copied" feedback, closes on Esc / Close / outside click; the markup and light/dark styles are in the bundle's page shell (`page/shell.html`, `page/shell.css`) and the handlers are `createHostFlow` in `browser/dialog-flows.mjs`), `serve.mjs` (localhost server, `createApp` exported for tests). `parse/toml.mjs` also parses `documents.toml` (title, url, description) into the Related documents panel and multi-line strings. `render/auto-layout.mjs` is used by the TOML pipeline.

One shared engine (`engine/`) renders each diagram folder (e.g. `examples/demo/`) into a self-contained `layout.html` (no runtime fetches except web fonts) and an Excalidraw scene `<id>.excalidraw`; both are generated, and no diagram needs engine edits. Diagram folders hold content only; see [examples/demo/](../../examples/demo/) for every format. Vocabulary: [terminology.md](../product/concepts/terminology.md).

## Build

- Build: `wsl.exe -e bash -ic 'cd <repo> && node engine/build.mjs examples/demo'`.
- Drift check: append `--check`; regenerates in memory and exits non-zero if `layout.html` or `<id>.excalidraw` on disk differ.
- Excalidraw: every build writes `<dir>/<id>.excalidraw` (e.g. `examples/demo/demo.excalidraw`); open it at excalidraw.com via "Open" (or drag the file onto the canvas), or in the VS Code Excalidraw extension.
- The diagram path resolves against the current directory, then the repo root. Any parse or validation error is a `FormatError` (`lib/errors.mjs`: `{file, line, path, message}`, the message starting with the file name when known, e.g. `servers/web01.toml:3: ...`). Libraries only throw it; the CLI entry points wrap their body in `runCli` (`lib/cli.mjs`), which prints `build: <message>` and sets a non-zero exit code. Nothing in `engine/parse` exits the process.

## Add a diagram

1. Create `<name>/` with `node engine/new.mjs <name>` (the empty folder: `topology.toml`, `server-types.toml`, `notes.toml`, `documents.toml`, `networks.toml`), or New diagram in the page, then add `servers/<id>.toml` files.
2. Run `node engine/build.mjs <name>`. Without `diagram.layout.json` the build arranges the diagram automatically (`render/auto-layout.mjs`, in memory; the file is not written); Save in the page writes it to pin positions. A folder with the retired Mermaid files (`diagram.mmd`, `diagram.json`, `details.md`, `layout.json`) and no `topology.toml` fails with "legacy Mermaid/Markdown diagrams are no longer supported: convert to TOML, see docs/tech/authoring.md" ([ADR-0017](decisions/adr-0017-retire-the-legacy-mermaid-and-markdown-pipeline.md)).

## Module map

Build (Node, ESM):

- `engine/build.mjs` - CLI loader: reads a TOML diagram folder (and `diagram.layout.json` when present), calls `prepareDiagram` (`browser/render.mjs`) and `renderModel`, writes or `--check`s `layout.html` and `<id>.excalidraw`.
- `engine/render/pipeline.mjs` - `renderModel({ config, model, layout, meta, kit, sections, notes, docs, drawings, networks, assets, validate })` -> `{ html, scene, routes, nets, ipNet, ent, typeList, svgBody, idx, viewBox, groupKit, edgeKeys, dataJson }`; `networks` is the `networks.toml` rows plus the derived ones (or null); `validate` runs the geometry check (the build sets it). Data flow: folder files -> `parse/toml.mjs` + `prepareDiagram` -> `renderModel` -> `layout.html` and `.excalidraw` (CLI) or the frame `srcdoc` (page).
- `engine/lib/util.mjs` - `readText` (CRLF-normalising reader); re-exports `esc` from `lib/text.mjs`. `fail` now lives in `lib/errors.mjs`.
- `engine/lib/text.mjs` - Node-free `esc`; the page bundle uses it in place of `util.mjs`.
- `engine/lib/files.mjs` - file-name constants of a diagram folder and archive, `serverPath(id)`. `engine/lib/ids.mjs` - id grammars, `slugify`, `sanitizeId`, `sanitizeName`. `engine/lib/net.mjs` - IPv4 / IPv6 and CIDR parsing. `engine/lib/cli.mjs` - `runCli`. See [ADR-0015](decisions/adr-0015-shared-helpers-and-server-field-table.md).
- `engine/lib/errors.mjs` - `FormatError` and `fail`. `engine/parse/layout-version.mjs` - `LAYOUT_VERSION`, `decideLayoutLoad`. `engine/parse/toml-escape.mjs` - the one TOML string escaper. See [ADR-0014](decisions/adr-0014-format-versioning-and-error-model.md).
- `engine/model/server.mjs` - the structured server facts (`serverFields`), the details markdown rendered from them (`serverSection`), card body lines (`serviceLines`, `cardJobs`, `cardUnits`), hardware normalisers, `groupUnits`, `globRegExp`; `engine/model/edges.mjs` - `edgeKey`, `endKey`, `isDashed`; see [IR vocabulary](#ir-vocabulary).
- `engine/model/server-fields.mjs` - `SERVER_FIELDS`, the table of `servers/<id>.toml` keys, and its page kit `serverFieldsKit`.
- `engine/page/bundle.mjs` and `engine/page/kits.mjs` - see [Bundler and kits](#bundler-and-kits). `engine/page/shell.html` and `shell.css` - the markup and styles of `diagram.html`.
- `engine/model/config.mjs` - Validation and defaults of the config object built from the `topology.toml` header (`id` = folder name, `proposedLabel`, `edgeLabels`, `groups`, `processes`); `checkConnections` checks group and process connection ids and body-line prefixes; `processAnchors` resolves process endpoints to body-line indexes.
- `engine/model/notes.mjs` - `parseNotes` (the notes parser and validation, also behind each TOML note) and `parseNoteText`.
- `engine/model/os.mjs` - end-of-support table (Ubuntu, Debian, CentOS, Oracle Linux, Windows Server); `osInfo` flags an OS as EOL against the build date.
- `engine/render/os-icons.mjs` - original OS glyph data (14x14 outline and filled paths per family) in `osIconKit`; `osIcons` serves the card pill (`render/svg.mjs`), and the same function is inlined as the generated runtime module `ui/os-icons` (see `GENERATED` in `page/assets.mjs`) for the details panel OS row. The Excalidraw export has no icons (text label only).
- Same module: `osFamily` (distro family id of an OS string, used for the icon; `osInfo` returns it as `f`) and `displayOs`: display-time shortening of stored OS strings (`Debian GNU/Linux 11 (bullseye)` -> `Debian 11 bullseye`, `Ubuntu 16.04.7 LTS` -> `Ubuntu 16.04 LTS`, `CentOS Linux 7 (Core)` -> `CentOS 7`, `Red Hat Enterprise Linux 8.6 (Ootpa)` -> `RHEL 8.6 Ootpa`, Rocky/Oracle shortened); used by the card pill (`shortOs`), the details panel OS cell and the Excalidraw label; stored data, the pill tooltip and EOL detection keep the original string.
- `engine/parse/networks-append.mjs` - `appendNetworks`: surgical append of derived `[[networks]]` (cidr only) to `networks.toml`; `shared-networks.mjs` holds `derivedCidr`, `derivedCidrs`, `withDerived` (defined plus derived networks) and the longest-prefix `assignNetwork`; `browser/save.mjs` `syncNetworks` runs it after Save with a base-checked write and one retry.
- `engine/render/validate.mjs` - normalises geometry in place (body / IP lines at the text padding, box widths, regions grown around their servers) and checks header bands and spacing. Split into small checks (`bandProblems`, `checkSpacing`) that `validateGeometry` calls in order.
- `engine/parse/types.mjs` - server-type table (labels, dark colours), entity typing, legend type list, type colours and CSS vars.
- `engine/render/svg.mjs` - SVG body elements + the element index (`idx`) the runtime addresses by position; network buttons (`idx.nodes[id].w`, -1 where an IP has no network); connections from the routes, group (`data-g`) and level (`lv:server` / `lv:process` in `data-tk`) markup; process endpoint lines (`.pl`). The entry point is `renderSvg({ model, layout, ent, nets, ipNet, routes, groups, meta })`, one options object (it replaced `renderSvgBody` with positional arguments).
- `engine/render/geometry.mjs` - `geometryMeta` (static per-diagram facts, shipped as `D.meta`) and `geometryKit`: drawn box extents, `fitBox` / `fitRegion` auto-sizing, `regionBounds` (smallest rectangle around a region's servers) and `resizeRegion` (manual resize clamped to it and to a 100 x 60 minimum), connection routing, connection label and firewall marker placement, spacing `problems`; inlined as the `canvas/geometry` runtime module so build and edit mode compute identical geometry. The router is a set of helpers in `geometryKit`: grid building (`grid`, `paint`, `paintHug`, `fillCosts`), the A* search (`search`, one function with an inlined binary heap; `heapPush` only seeds it; `turnCost`, `traceBack`), port choice (`port`, `centre`, `span`, `facing`), marker placement (`stations`, `placeFirewall`, `placeLabel`) and the incremental machinery (`routeWith`, `gridDiff`, `gridSame`, `rectDiff`, `fpClear`; see [Routing and the route cache](#routing-and-the-route-cache)). `route(layout, meta, measured)` is `routeWith` without a previous state.
- `engine/render/firewall.mjs` - firewall glyph (`fwGlyph`).
- `engine/render/edge-key.mjs` - connection legend rows (HTML panel, export data incl. one row per connection group), labels from `edgeLabels`; `groupAssets`: per-group arrowhead markers and `--gc` colour CSS.
- `engine/render/viewbox.mjs` - content bounds (incl. routed connections) → initial `viewBox`.
- `engine/page/layout-html.mjs` - `layout.html` shell: top area (`#ta`), SVG, Legend / Networks / Notes / Related documents / details panel markup.
- `engine/page/layout-html.mjs` - `renderScene(...)` builds the **scene** (see [Shell and scene](#shell-and-scene)); `renderLayoutHtml({ scene, cssPage, js })` wraps it in the shell.
- `engine/page/data.mjs` - the `layout-data` JSON blob for the runtime (incl. `meta` and the Legend's connection switches `edgeSwitches`).
- `engine/export/excalidraw.mjs` - Excalidraw scene from the computed geometry: regions (bound title), servers (one group each: box, title, body / IP / OS text), connections as arrows bound to their boxes, labels as free text on a white pill at the view's label spot (moved or wrapped onto two lines when it would touch a firewall, server or other label), firewall zigzags, a legend block left and notes as sticky rectangles right; ids and seeds are hashes of entity keys, so re-exports diff cleanly. The look is the monochrome whiteboard of the Sketch skin (no fills, dashed regions, title above the box, red only for connection groups and firewalls, pale yellow notes, legend with line styles only). Font: `SANS` / `MONO` (default 5 Excalifont, hand-drawn; 2 Helvetica, 3 Cascadia for a clean look). There is one look only: the former `clean` style switch (coloured cards, type legend) was removed, so `renderExcalidraw` takes no `typeList` or `typeColors`.
- `engine/page/assets.mjs` - CSS manifest (order = cascade) and the runtime module manifest, checker and inlining.

Runtime (browser, inlined as one `<script>`): `engine/runtime/define.js` creates `window.InfraDiagram` with `define(name, deps, factory)`; every other file is private helper functions (no dependencies on the factory) followed by one `InfraDiagram.define("<folder>/<file>", [deps], function ({ <params> }) { ... return { exports }; });`; the factory receives its dependencies as one object keyed by the camel-cased module name, and its exports land in `InfraDiagram.modules[name]`. `script()` in `page/assets.mjs` wraps every module in its own function scope (`wrapModule`), so the helpers at a file's top level are private to it and cannot collide with another module's; tests that evaluate a runtime file in a shared `vm` context wrap it the same way (identically in every loader of one file, so coverage offsets merge). Rules the build enforces (`build: engine/runtime/...: ...`): the name matches the path; each dependency is a module listed earlier in `RUNTIME` (assets.mjs); its parameter is the camel-cased file name (`ui/export-columns` → `exportColumns`); every `param.x` used is exported by that module; no unused or undeclared module references; no `</script`. Each file stays valid standalone (`node --check`).

- `engine/runtime/ui/core.js` - shared state (`ctx` incl. the current `routes`, `D`, `svg`, `els`, `ents`, localStorage keys `<id>-<name>` (`lsGet` / `lsSet` / `lsDel`), clipboard / download helpers) and the runtime's wiring, all declared in this one file: **services** (`provide(name, fn)`, read as `core.services.<name>`; ten fixed names - `getState`, `isEdit`, `fit` from the canvas init, `view`, `viewNode`, `title`, `route`, `rerender` from `canvas/model`, `beforeSelect` (return `false` to veto a selection) and `pending` from `ui/server-edit`; a second `provide` for a name, an unknown name or a non-function throws, `revoke(name)` is for tests), **events** (`on(event, fn)` returns an unsubscribe function, `emit(event, ...args)` calls subscribers in subscription order and logs a throwing subscriber with `console.error` without stopping the others; `EVENTS` is the one list: `panel (key, panelElement)` after `ui/details` filled the details panel, `render ()` after `canvas/model` drew a state, `scene (scene, changed)` after `ui/scene` swapped a new scene in (see [Shell and scene](#shell-and-scene)); an unknown event or the same handler twice throws) and the **host** (`core.host`, filled once by `attachHost(host)`, also reachable as `InfraDiagram.attachHost`; a second call throws, `detachHost()` is for tests; fields: `noteParser(text) -> { title, date, paras }` and `serverEditor` with `source`, `apply`, `add`, `duplicate`, `regionTypes`, `addRegion`, `move`, `renameNetwork`; both are `null` until attached). Modules read `core.host.serverEditor` at call time and never `window.InfraDiagram.*`.
- `engine/runtime/ui/skins.js` - skin switch and per-skin server chrome (header, icon, IP pills, label pills, OS pill size, ellipsis and EOL marker placement (`sizeOs`), network button placement); `sync` after geometry moves; `widths` / `labelWidths` (measured) for routing; re-routes via `services.route` when the chrome is rebuilt.
- `engine/runtime/ui/scene.js` - `replaceScene(scene)` (also `InfraDiagram.replaceScene`): the scene swap, see [Shell and scene](#shell-and-scene).
- `engine/runtime/ui/legend.js` - type switches, "Show all", connection switches (levels and groups), "Connection labels" and "Display System Information" switches.
- `engine/runtime/ui/selection.js` - related-entity graph, dim / select, opens the details panel.
- `engine/runtime/ui/clear-click.js` - empty-click deselect: `isEmptyTarget`, `isEmptyClick` (pointerdown and click both on empty places, primary button, under 4px movement, no drawing tool) and `clearSelection` (selection plus network filter, like Esc; skipped while a server form has pending edits via `services.pending`).
- `engine/runtime/ui/networks.js` - network filter: Networks panel clicks, dims servers outside the active network; `toggleNet` for network buttons (reveals the network in the panel).
- `engine/runtime/ui/panels.js` - collapsible panels; places the left and right columns below the top area and publishes its bottom as `--ta-b`.
- `engine/runtime/ui/export-columns.js` - static legend and notes columns for exports.
- `engine/runtime/ui/copy.js` - click-to-copy + "Copied" hint.
- `engine/runtime/ui/details.js` - mini Markdown renderer + details panel (the OS row is rendered from the structured `e.os`: first row of the generated Key / Value table, else its own `.po` table after the tag; EOL badge, Confluence link, network buttons after IPs). `md(src)` is a small block loop over named helpers: `inline` (code, bold, http(s) links only), `mdTable` / `mdRow` / `mdCells`, `mdList`, `mdRun` (collect a run of lines), `mdParagraphLine`; a line such as `#tag` with no space after `#` is plain text, not a heading.
- `engine/runtime/ui/export-image.js` - SVG / PNG export (CSS inlined, fitted view, background, network buttons stripped), file names `<id>-<skin>.svg|png`.
- `engine/runtime/ui/init.js` - `init` (event wiring: skin buttons, export buttons, details close, SVG clicks, network buttons, Esc), `editChanged`, keyboard access (every server and region title gets `tabindex="0"`, `role="button"`, an `aria-label` such as "Server Service A" and `aria-pressed`; Enter / Space select it, a dashed focus ring `#fr` follows a keyboard-focused node through the `render` event, ARIA roles and names for the toolbar, the layout-editing group, the status line and the pen options), console API on `window.InfraDiagram` (`setStyle`, `toggle`, `showAll`, `select`, `setNet`, `exportSvg`, `md`, `related`, `ctx`).
- `engine/runtime/canvas/geometry` - generated from `render/geometry.mjs` (`geometryKit`).
- `engine/runtime/canvas/model.js` - layout state (`state.st` draft, `state.on` edit mode), geometry moves (children follow, a dragged server grows its region, `resize` moves region sides via `resizeRegion`), the edit-mode resize handles (`#rh`, 8 per region, hidden outside edit mode and removed from exports), apply to the DOM (connections re-routed, spacing violations marked `.bad`), screen → SVG `point`, `regionAt(layout, point)` (smallest region under a point; used by the context menu and the drag-drop region change).
- `engine/runtime/canvas/zoom-pan.js` - fit, zoom buttons / keys / wheel, pan.
- `engine/runtime/canvas/draw-kit` - generated from `render/draw-kit.mjs` (`drawKit`), like `canvas/geometry`.
- `engine/runtime/canvas/draw.js` - drawing tools: strokes live in `<g id="dw">` inside the SVG (same coordinate space as the diagram, so they zoom and pan with it and are cloned by the SVG / PNG export); the layer is rendered at build time from `drawings` and re-rendered on each change; while a tool is active a capturing pointer handler on the SVG keeps pan, node drag and selection from starting. Drawings are kept apart from `state.st`, so layout reconciliation never touches them.
- `engine/runtime/canvas/context-menu.js` - right-click "Add Server" / "Add Region" / "Duplicate server" menu (edit mode, file-backed pages only).
- `engine/runtime/canvas/edit-mode.js` - edit mode: drag + snap (one render per animation frame), drafts, `diagram.layout.json` copy / download / reset; boots the page via `ui/init`.

CSS (`css/svg/*` is also embedded in exports):

- `engine/css/svg/tokens.css` - per-skin colour / font tokens (the `/*DARK<*/.../*>DARK*/` block is parsed by `export-image.js`).
- `engine/css/svg/base.css` - base servers, regions, connections.
- `engine/css/svg/export.css` - notes and legend columns in exports.

Keys: `nodeKey(kind, id)` and `parseKey(key)` in `lib/keys.mjs` build and read every key; nothing concatenates `"n:" + id` or slices `key.slice(2)` by hand. The serialized forms are fixed (pinned in `keys.test.mjs`): `n:<id>` server (kind `server`), `c:<id>` region (`region`), `e:<key>` connection (`edge`), `g:<id>` connection group (`group`), `lv:<level>` connection level (`level`). `parseKey` splits at the first colon, so ids may contain colons; an unknown prefix gives `{ kind: null, id: key }`. The same functions reach the page as the runtime module `ui/keys` (a kit); `geometryKit` receives them as its second argument. `meta` field names (`tl`, `bl`, `nb`, ...) are kept: they are part of the page data (`D.meta`) and renaming them changes every generated page, so it is left for a change that also versions the data.

### Metrics and the box sizing contract

`render/metrics.mjs` holds the one `METRICS` table (frozen): header height, text padding, line pitches, character widths per text kind, paddings and gaps of regions, pill sizes, the card icon, the per-skin fallback character widths. Node modules import it (`auto-layout`, `validate`, `excalidraw`, `svg`); the page gets the same table as the runtime module `ui/metrics` and `geometryKit` receives it as its first argument (`geometryKitOf(metrics, keys)`; `geometryKit()` is the Node call with the real table), so build, auto layout and edit mode cannot drift apart. A size that appears in a second place is a bug: add it to the table.

`kit.boxFor(meta, x, y)` is the one definition of a server card: width from the longest of title, body line, IP, OS pill and hardware strip, height from the rows (body lines, hardware strip, OS pill) plus the IP lines, and the text positions (`title`, `body`, `ip`). `fitBox` (width), auto layout (size and positions), the saved-layout reconcile in `browser/render.mjs` (height and text positions) and edit mode (`viewNode` with system information off) all call it. `box-for.test.mjs` renders six server shapes (no services, many services, EOL OS, long name, hardware strip, three IPs) and checks `boxFor` against the saved geometry and the drawn SVG.

### Routing and the route cache

`geometryKit().route` is an A* over a sparse orthogonal grid. Its tables are typed arrays validated by a generation stamp (no per-search clearing), the open set is a binary heap in typed arrays, region, hug and obstacle flags of the grid are painted per obstacle (binary search on the grid coordinates) instead of tested per point, step costs are precomputed per grid segment, and label and firewall placement look up obstacles in a bucket index (`boxIndex`, `cost`). Everything keeps the arithmetic and the tie-breaking of the original router: `routes-golden.test.mjs` pins the routes of generated 20, 100 and 200 server diagrams to the output of the previous implementation. `render/route-cache.mjs` (`routeAll`) adds a pure cache: the result of `renderModel`/`renderDiagram` carries `routeCache` ({ sig, routes, state }), and passing it to the next render reuses the routes when the signature (box geometry, region geometry, connections, saved waypoints and labels) is unchanged; `browser/app.js` keeps it between edits. When the signature differs, `kit.routeWith(layout, meta, measured, state)` routes incrementally ([ADR-0020](decisions/adr-0020-incremental-routing.md)): the `state` of the previous run holds, per connection, the result of each search with the window of the grid it touched, and the placed marker and label with the area they were scored in; the new run builds its grids, diffs them with the old ones and searches again only the connections whose window changed (same lines in the same order, same flags, same end rectangles), and places again only the markers and labels near a changed box. The result is the one of a full re-route, to the last bit (`route-incremental.test.mjs`). The frame keeps its own state in `canvas/model` (`routeEdges`), so a drag step or a scene swap also routes incrementally. A box edit still searches again every connection whose window spans one of the changed grid lines (about 30 % of them at 400 servers for a height change); the grid lines span the plane and the heap tie-breaking makes the result depend on every line in the search area, so a smaller rule would not be exact.

## Page behaviour

- **Server card**: header bar with the name and icon, body lines (jobs without the `cron:` entries via `cardJobs` in `model/server.mjs`, so a card with only cron jobs has no jobs section; the data and the editor keep every job), OS pill, IP pills. Box width and height are computed from content (`fitBox`, auto-layout `size`, saved-layout reconcile in `browser/render.mjs`) and a saved size smaller than the content is grown, never clipped. The header shows the short host name: for a DNS name (contains a dot, not an IPv4 / IPv6 literal) only the first label (`hostLabel`), otherwise the name as is; servers whose short labels would collide (`displayLabels`) show their full names; the data (`name`, details panel, editor) is never shortened. The text is 12px semi-bold, starts 10px from the left and is centred vertically in the header bar in Clean, Dark and Swiss (`headerTitle` in `geometryKit`, CSS `dominant-baseline: central`; Sketch keeps its title above the box); box width uses the displayed label (`meta.nodes[id].tl`, measured at runtime). Labels longer than `TITLE_MAX` (34 chars, `render/geometry.mjs`) are cut with an ellipsis; the full name is always in an SVG `<title>` tooltip. In TOML diagrams the body has two sections separated by a thin divider (`.dv`, drawn by `nodeChrome` in `runtime/ui/skins.js`; no extra height, like the other dividers): first `jobs` (first 4 plus "+N more"), then `services`, `rmi_services` and `systemd_services` (the last two each capped the same way); an empty section and its divider are omitted (`serviceLines` in `parse/toml.mjs`, `node.jn` = job line count, `meta.nodes[id].nj`). Process-connection anchors (`from_service` / `to_service`) match `services` only. The details panel always lists everything.

- **Top area**: skin switch, zoom and drawing tools (left), "SVG" / "PNG" / "Edit layout" (right); buttons are opaque in every skin.
- **Skins**: Sketch | Clean | Dark | Swiss (default Clean; `?style=sketch|dark|swiss`, remembered in localStorage). One SVG, same geometry: the skin is a class on the `<svg>` plus per-skin CSS and the runtime chrome renderer; Sketch has no chrome.
- **Panels**: Legend and Networks in a left column, Notes and Related documents in a right column, all floating over the diagram just below the top area; each collapses via its header (default open, collapsed below 700px; state in localStorage). The right column drops below the left one when the window is too narrow; a column scrolls when taller than the window.
- **Legend**: type switches dim a server type and its connections to 10%; connection switches ("Server connections", "Process connections" when the diagram has processes, one per connection group, e.g. "Job 104 connections" with its colour swatch) dim connections the same way, and a connection shows only while every switch it belongs to is on; "Show all" resets; "Connection labels" (default off) shows connection labels; "Display System Information" (default on; stored under the legacy `os` key) shows OS pills and the hardware strip together; off hides both and the card shrinks (`viewNode` / `view` in `canvas/model.js` move the IP pills up and cut the height for display only, the saved layout keeps the full size; the details panel is unaffected). OS pills sit left-aligned 3px above the first IP pill and hidden where they would touch a body line; in TOML diagrams a server with `os` reserves its own 16px row between the body lines and the IP pills (`meta.nodes[id].os`), so the pill never collides. EOL is checked at build time, so `--check` can flip when a version crosses its date. All switches are remembered in localStorage.
- **Network filter** (`networks.toml` plus the networks derived from server IPs, see [authoring.md](authoring.md#networks)): the Networks panel lists the tree with CIDR, name and host count (0 hosts muted); clicking a network dims servers outside it, regions with no member and connections not between two members; one at a time; click it again, Esc, or "Show all" clears; combines with the type switches.
- **Network buttons** (when the diagram has networks): a 14x13 network glyph 2px right of each IP pill (Sketch: of the IP text) whose IP lies in a defined network, and after such IPs in the details panel; it activates the deepest network containing the IP (opens the Networks panel, scrolls to it), and clicking it again clears; no button for IPs outside every network or network addresses. In a box too narrow it slides left over the pill's padding and is hidden if it would cover the IP text. Never exported, hidden in edit mode.
- **Clicks** (not in edit mode): a server header / title, OS pill or region title dims everything unrelated and opens its details section in the details panel (over the right column, or a bottom sheet below 760px; the diagram never resizes); the details panel always shows the OS row, with an EOL badge when applicable; a body or IP line copies its text; Esc or an empty click clears.
- **Zoom**: "−" / "+" / "Fit", keys `+` / `-` / `0`, mouse wheel at the cursor (no modifier needed; over a panel the wheel scrolls the panel); range 0.25x-8x. Drag empty canvas to pan at any zoom (not in edit mode; a drag never selects or copies). Pan and zoom keep the smaller of ~100px or 15% of the diagram on screen per axis. Zoom narrows the live `viewBox`; the fitted one is kept in `data-fit` and used by exports.
- **Connections**: routed automatically from the current geometry, at build time and live in edit mode: a sparse orthogonal grid over server and region borders, A* minimising length plus bends plus penalties for crossing foreign regions, hugging region borders and narrow channels (servers are hard obstacles); ports sit on the border side facing the route, spread up to 20px apart when they share a side, and line up so facing servers get a straight line; a process endpoint leaves or enters its server's left or right side at its body line; corners are rounded. The firewall marker and connection labels take the free spot nearest the path's midpoint (clear of servers, region titles and borders, other markers). `via` waypoints and a fixed `label` in `layout.json` override.
- **Edit mode**: `?debug` or "Edit layout"; drag servers and regions (children follow, connections re-route live; "Snap 5px", Shift disables); a dragged server grows its region to keep padding and header band; each region has 8 invisible resize handles (an 8px hit band along its rounded outline - edge strips and corner arcs; nothing is drawn, only the resize cursor appears on the border) that move its sides, never past its servers or a 100 x 60 minimum, with Snap / Shift as for moves, and the result is an ordinary layout change in `clusters` (unsaved-change tracking, Save, drafts) without moving servers or panning; dropping a server (pointer position, judged against the regions as they were when the drag started) in another region puts it there, dropping it outside every region takes it out of its region (see `authoring.md`); servers and regions breaking the spacing rules get a red outline; "Copy layout" / "Download" export geometry to paste over `diagram.layout.json`; "Reset" drops the draft; in the generated `layout.html`, drafts persist in localStorage while edit mode is on, keyed by a hash of layout + diagram text (the file-backed page keeps no drafts: it saves to `diagram.layout.json`).
- **Export**: "SVG" / "PNG" (2x) export the current skin and visible state at the fitted view, with a legend column left (plus the active network filter, if any) and all notes right; dimmed stays dimmed; related documents are not exported; web fonts are not embedded.
- **Per-diagram names**: localStorage keys and export file names use the diagram `id` as prefix; the `proposed` legend entry, the connection legend labels and connection groups come from `topology.toml`.

## Storage and security

- **Store** (`lib/store.mjs`): one sub-folder per diagram under `local/`; file names pass `lib/names.mjs` (allow-list, no `..`, at most two folder levels, no Windows device names, no trailing dot or space, case-insensitive duplicates refused). A save checks every file's `base` first (409 on any difference, nothing written), then stages all files as fsynced temp files, renames them all and restores the earlier contents when a rename fails. Leftover `.<hex>.tmp` files are swept at start and before each save.
- **Server** (`serve.mjs`): loopback only; every response has `Cache-Control: no-store`, a CSP, `Referrer-Policy: no-referrer`, `nosniff` and CORP `same-origin`; the Host, Origin and `Sec-Fetch-Site` checks run on every request; bodies over 8 MB get 413 early; request timeout 30 s, headers 10 s. Details: [authoring.md](authoring.md#local-server-api), [ADR-0004](decisions/adr-0004-local-server-storage.md).
- **Diagram frame**: the page renders the diagram into an iframe `srcdoc` with its own CSP meta (`connect-src 'none'`, inline script and style, data and blob images, fonts from Google Fonts), so text from an imported archive cannot call the API. There is no `sandbox` attribute yet: it needs a `postMessage` host interface ([ADR-0013](decisions/adr-0013-adopt-refactoring-roadmap.md)).
- **Archive reader** (`lib/zip.mjs`): path rules, entry and size caps while inflating, CRC check; see [authoring.md](authoring.md#diagram-archive).

## Shell and scene

A diagram page is a **shell** that lives as long as its frame (the document, toolbar, `<style id="css-page">`, the runtime script, the controls) around a **scene** that an edit replaces ([ADR-0019](decisions/adr-0019-page-shell-and-scene-swap.md)). The scene (`renderScene` in `page/layout-html.mjs`, a plain object of strings):

| Field | Where it goes |
| --- | --- |
| `shell` | key of the shell: `JSON.stringify([diagram id, hasNetworks])`; the frame bridge swaps only into a page with the same key |
| `title`, `cssSvg` | `document.title`, `<style id="css-svg">` (skin styles plus the type and group styles) |
| `viewBox`, `svg` | the `viewBox` of a fresh page, and the inner markup of the diagram `<svg>` (defs, body, `<g id="dw">`) |
| `legendKey` | inner markup of `.lk` (the connection key; the switches are built from `data`) |
| `nets` | inner markup of `#wl`, `null` without networks |
| `noteCount`, `notes`, `docs` | `Notes (n)`, inner markup of `#nl` and `#dl` |
| `data` | the `layout-data` JSON text |

`InfraDiagram.replaceScene(scene)` (`ui/scene.js`) returns `{ ok: true }` or `{ ok: false, reason }`. It refuses first, without touching the page, when the scene is malformed, belongs to another diagram id, or adds or drops the Networks panel; an exception later also returns `ok: false` (the caller reloads the page). The order: replace `D`, the svg children, `els` and `ents` in place (`core.replaceScene`; `D.layout` keeps its identity, it is the model's `base`), the style sheet, the title and the panel lists that changed; rebuild the legend; map the network filter to the new list; emit **`scene (scene, changed)`**; rebuild the chrome, render (the **`render`** event fires) and fit; restore the selection. Subscribers of `scene`: `canvas/model` (new `state.st`, resize handles), `canvas/zoom-pan` (new base view box; zoom, pan and fit mode stay), `canvas/edit-mode` (draft key, edit marks), `canvas/draw` (the strokes layer), `ui/init` (focus ring, focusable cards), `ui/notes-edit` (reloads its texts when `changed.notes`). A full load and a swap give the same DOM and data; `scene-swap.test.mjs` checks it for every kind of edit.

The browser side: `edits.mjs` renders (route cache and all) and calls `bridge.replace(result)`; the scene is passed as an object to `frame.contentWindow.InfraDiagram.replaceScene` (same-origin `srcdoc`, no `postMessage`, the strings are not copied). Open, new and import call `bridge.show`; `replace` falls back to `show` when the shell key differs, the frame is not ready, or the runtime refuses or throws. The frame's CSP is unchanged.

## Versions and errors

- `topology.toml` may carry `format_version = "1"` (absent means 1); `checkFormatVersion` runs first in `mergeFolder` and refuses a newer value. Additive keys never bump it ([ADR-0014](decisions/adr-0014-format-versioning-and-error-model.md)).
- The layout file has an integer `version` (`LAYOUT_VERSION`), always written by Save; a newer one opens with an automatic arrangement and Save leaves it untouched (`decideLayoutLoad`).
- Invalid input throws `FormatError` (`lib/errors.mjs`); libraries never exit. `build.mjs` and `new.mjs` wrap their body in `runCli`. Open gaps: `browser.mjs` and `serve.mjs` do not catch it, and `tomlModel` errors for server files lack file names.

## Toolbar and file flows

The toolbar of `diagram.html` (`page/shell.html`): **New diagram**, **Open saved diagram**, **Import diagram**, **Import servers**, **Export**, **Save**, **Host script**. **Import servers**, **Export** and **Save** are disabled until a diagram is open, and **Save** is enabled only with unsaved changes. Each dialog is built by `browser/dialogs.mjs` and filled by `browser/dialog-flows.mjs`.

- **Save** (`browser/save.mjs`): settles an open form, asks before replacing an existing folder of an imported or new diagram, sends the changed files with their `base` text in one `PUT /api/files`, then appends derived networks to `networks.toml` (`syncNetworks`). A locked layout (newer version) is not written.
- **Export** (`exportDiagram`): packs the in-memory files, including unsaved edits, into `<id>-<timestamp>.diag.zip`; no server is involved.
- **Import diagram**: `unpackDiagram` (`lib/diagrams.mjs`) reads the archive as untrusted input and opens it as an unsaved in-memory diagram; dropping a `.diag.zip` on the page does the same.
- Without the local server (`diagram.html` from disk) the page works in memory only: Save is unavailable, Export and Import diagram work.

## Bundler and kits

`engine/browser.mjs` writes `diagram.html`: it inlines the page shell (`page/shell.html` and `page/shell.css`, read at build time), the bundled modules and `browser/app.js`.

- `page/bundle.mjs` is the module bundler. Entry modules are the `require("...")` names used by `browser/app.js` plus `browser/render.mjs`; their imports are followed (single-line and multi-line named imports and `export { name } from "..."` re-exports; anything else is an error). Modules that run in the page may not import Node modules: `lib/text.mjs` holds the Node-free text helpers (`esc`, `unq`) and `lib/util.mjs` re-exports them, so the bundler maps `lib/util.mjs` to `lib/text.mjs`; the one Node import left in bundled code (`basename` from `node:path`, used by `model/config.mjs`) has a one-line shim in the bundler.
- `page/kits.mjs` is the registry of kits: functions written once in Node (`geometryKitOf`, `drawKit`, `osIconKit`, `keysKit`, `metricsKit`) and inlined into the page through `Function.toString()` as runtime modules. A kit body may only use its own locals, its parameters and language built-ins; `engine/test/kits.test.mjs` scans each kit for free variables. A kit may take arguments (`args`: `{ json: value }` is inlined as JSON, `{ kit: fn }` as the call of another kit), which is how `ui/metrics` and `canvas/geometry` receive `METRICS` and the keys; a kit parameter must not be named like a runtime module parameter (`keys`, `metrics`), or the module loader reports an undeclared dependency.

## Static analysis scope

`.sonarcloud.properties` (read by SonarCloud automatic analysis) excludes the
generated outputs `diagram.html` and `examples/**/*.html` (and the exported
`.excalidraw` scenes) from analysis, so issues and duplication are measured on
hand-written source only. Engine tests and examples are excluded from
duplication checks (`sonar.cpd.exclusions`). Exclusions take effect only after
the next analysis, which runs on push. Decision, intentionally open rules and
how to re-check: [ADR-0011](decisions/adr-0011-static-analysis-sonarcloud.md).
